## Product objective

The redesign applies the principle that FocusFlow should optimize for **consistent meaningful work**, lower cognitive load, productive habits, and long-term usefulness rather than surface-level engagement. The implementation does not add another disconnected module. It exposes the existing task, project, focus, notes, reminders, calendar, search, and knowledge relationships at the moment they can help a person act.

## Research basis

The research record is preserved in `docs/PRODUCT_UX_RESEARCH_FOCUSFLOW_V2.md`. Nielsen Norman Group describes cognitive load as the mental resources required to operate an interface and recommends reducing extraneous load through less clutter, familiar mental models, and offloading memory and decision work [1]. A systematic review of 41 digital behavior-change studies found feedback/monitoring, cues, and goals/planning to be common techniques, while also identifying long-term-adoption risks when systems demand too much proactive effort [2]. Material Design and WCAG 2.2 support clear hierarchy, focus control, semantic structure, adequate targets, and accessible defaults [3] [4] [5]. First-party patterns from Apple, Raycast, Notion, Todoist, and Linear reinforce structured navigation, keyboard-first commands, quick capture, scoped work, project context, and momentum [6] [7] [8] [9] [10].

> The product decision is to make the next meaningful action obvious, make capture cheap, and make progress explainable. Engagement signals are subordinate to work outcomes.

## Implemented experience

### Today’s Mission

The Dashboard now opens with a `Today’s Mission` card generated by the deterministic `FocusFlowCoach`. It chooses one next task using overdue status, due date, priority, goal context, and estimated effort. It explains why the task was selected and gives the user a direct **Start focus** action. When there is no unfinished task, the card gives a useful capture prompt instead of an empty-state dead end.

When the day is overloaded, the card uses recovery language and a **Rebalance** indicator rather than guilt or arbitrary streak pressure. It reports the number of unfinished tasks and estimated planned minutes, so the user can recognize an unrealistic plan before investing more attention into it.

### Quick Capture

The Dashboard now provides a real Quick Capture sheet that persists offline through existing controllers. It supports Task, Note, Reminder, Calendar, and Project capture in one focused interaction. The sheet uses a short prompt, a clear type selector, explicit save feedback, keyboard submission, and no silent remote mutation. Voice-note capture and binary asset ingestion remain platform-specific flows rather than fake buttons; the current surface keeps those capabilities in their dedicated modules.

### Focused navigation

The Dashboard app bar now reserves primary space for Global Search, Quick Capture, notifications, and customization. The many secondary module destinations are grouped into a labeled **More destinations** menu. Ctrl+K and Cmd+K continue to open the Command Palette. This reduces equal-weight navigation competition while keeping every module within two interactions.

### Project-to-task continuity

Project progress cards are now actionable. Selecting a project opens its project-filtered Tasks route through the existing `project` query context. This makes the Project → Task relationship visible at the point where progress should turn into action. The redesign reuses existing project, workspace, goal, milestone, task, and event infrastructure rather than adding duplicate storage.

### Professional motivation

The delivered motivation layer is deliberately restrained. It uses visible progress, focus-time feedback, milestone context, meaningful completion language, and overload recovery. XP, leaderboards, streak pressure, and celebration effects were not added because the current product does not yet have an opt-in motivation model or evidence that those mechanics would improve meaningful work for this user. This avoids optimizing the wrong metric.

## Design system decisions

| Area | V2 decision | Reason |
|---|---|---|
| Hierarchy | Mission first, supporting widgets second, secondary destinations in a menu | Directs attention toward action instead of module inventory |
| Copy | Specific, recovery-oriented, non-guilt language | Supports sustainable engagement and realistic planning |
| Color | Existing Material 3 solid accents; primary container for the mission | Uses color for status and focus, not decoration |
| Interaction | Keyboard shortcuts, Quick Capture, actionable project cards | Reduces navigation and memory burden |
| Density | Keep supporting metrics, but make them subordinate to one next action | Preserves power without requiring a dashboard scan |
| Accessibility | Semantic mission label, named controls, keyboard paths, standard Material targets, logical reading order | Aligns with Material and WCAG guidance |
| Offline behavior | Local task/note/reminder/calendar/project persistence | Keeps capture and focus useful without a network |
| Motion | No new decorative motion; existing reduced-motion settings remain respected | Avoids adding attention cost to frequent actions |

## Known limits and next evidence needed

The current deployment architecture remains unchanged: Vercel serves the Flutter static shell through Express, while the FastAPI `/api/v1` service is independently tested. Offline capture is therefore the dependable behavior at the client boundary; durable multi-device synchronization still requires the previously documented external database and storage deployment step.

The Coach is deterministic and explainable. It does not claim cloud AI inference, and it does not send telemetry. Future local open-source AI can enrich recommendations through the existing contracts only after it can explain its sources and preserve user control. The next research cycle should measure time-to-first-action, capture completion, daily mission completion, overload recovery, and accessibility task success with real users before adding more motivation mechanics or animation.
